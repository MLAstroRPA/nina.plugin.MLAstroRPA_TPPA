# MLAstroRPA+TPPA v2.1.1.0-beta

Pre-release of v2.1.1.0 — honest feedback when a **wireless** connect fails, plus an automatic **Serial** fallback.
The installer reports version `2.1.1.0` (Windows Installer has no `-beta` suffix).

**Requires device firmware 1.3.0 or newer**

## ✨ Highlights
- **Wireless failure is reported** — a failed wireless connect now says *"Wireless connection failed (…). Trying to scan the serial (COM) connection…"* instead of silently succeeding on a private COM port
- **Automatic Serial fallback** — when the COM device is found, the plugin switches the Connection type back to **Serial** by itself and MLAstro stays the COM owner, so the UI/telemetry match the transport actually in use
- **The connect toast names the transport** — *Successfully connected to MLAstroRPA over Serial (COM5)* / *… over Wireless (WebSocket @ MLastroRPA.local)*
- **Bounded retry** — wireless connect retries only a few times inside a 5 s window (per-attempt resolve/connect timeout) and then fails with the reason; auto-reconnect after Reset ESP32 is capped at 30 s
- **Warning next to the Connection type selector** (orange ⚠️) — switching Serial ↔ Wireless disconnects the current session
- TPPA **Test Connect** tests the wireless path first when Wireless is selected

## 🔧 Fixed
- A failed wireless connect (mDNS/DNS not resolving, wrong address, refused handshake) reported success — the driver silently fell back to its own COM port
- Retrying a wrong address could run for minutes without ever reporting failed
- Auto-reconnect could hang on a bad address instead of telling the user why
- The connection error dialog now shows the reason (address/handshake)

## ⚠️ Notes
- **Pre-release build** — same code as the normal 2.1.1.0 build; please try the CONNECTION tab cases and report anything odd before it is promoted to a normal release
- No protocol change — works with firmware 1.3.0+ over both Serial and Wireless
- If the wireless address is wrong (mDNS down), enter the device IP instead (`192.168.4.1` in AP mode)
- Switching Serial ↔ Wireless always disconnects the current session (an alignment in progress is stopped)
